# Android 侧载 ADV 开发者身份验证(国内四厂)

## 背景

2026-11-09 起,OPPO、vivo、小米、荣耀(移动智能终端生态联盟)在中国大陆对**侧载安装**的 APK
启用开发者身份验证(ADV,Android Developer Verification)。未验证应用安装时会弹
「开发者身份未验证」提示(如 OPPO 的"个人信息收集提醒 / 信息收集风险"同属这一套合规弹窗),
用户手动确认后**仍可继续安装**,不是硬拦截。

- 验证对象:开发者实名身份 ↔ **包名 + 签名** 的归属关联。不是病毒检测,不审计代码。
- 四家**验证结果互认**:任选一家做一次即可。
- 与 Google 海外 ADV 是两套体系;Google 那套不含中国大陆无 GMS 设备,**不需要向谷歌申请**。
- 商店在架应用由平台自动验证;**纯官网/侧载分发的应用(我们)必须手动补验证**。

## 流程(OPPO 开放平台实操,2026-11-18 已完成)

1. 注册开发者账号 + 个人/企业实名认证(用户已有账号,免此步)。
2. 「应用分发 → 应用管理 → 应用验证」→「新增验证」,上传**含签名的 APK**。
3. 勾选协议政策 → 提交,机审即时生效,状态直接「已验证」(2026-11-18 01:34)。
4. 结果同步金标联盟四家(OPPO/vivo/小米/荣耀互认)。

### 实操关键:不要用平台的"APK 空包"模板

- 页面提示下载 `OPPOSignVerifyPackage.zip`(内含 `OppoSignVerify.apk` 模板),
  签名后上传——但模板自带包名 `com.oppo.testsignature`,平台判定
  「该应用未在当前账户下」并要求先去「移动应用认领」,而该包名在认领里也查不到,死路。
- **正确做法:直接上传真实发布的 `app-release.apk`**(包名 `cn.quniv.nienie_mobile`、
  发布密钥签名),平台解析出真实包名/应用名/签名后即可直接提交,一次通过。
- 上传入口是隐藏的 `input.el-upload__input`(accept=.apk),不是"选择文件"按钮本身。

## 维护注意

- **换包名或换签名必须重新提交验证**(签名是互认的锚)。官网 APK 与 CI 发布必须用同一签名密钥。
- 商店在架包更新会自动同步,侧载包不会。
- 未验证只影响安装摩擦(多一次确认),不影响功能;用户当前点「继续安装」即可。
- 另:安装时的「检测结果:涉及敏感权限」指 `CAMERA`(扫码配对),属正常提示。
